AWS Secrets Manager – Complete Interview Questions and Answers
---------------------------------------------------------------

1. What is AWS Secrets Manager?
---------------------------------------------------------------
Amazon Web Services Secrets Manager is a fully managed service used to securely store, manage, retrieve, 
and rotate sensitive information such as:
Database credentials
API keys
Tokens
Passwords
SSH keys
Third-party credentials

2. Why Do We Need AWS Secrets Manager?
---------------------------------------------------------------
Instead of hardcoding credentials inside applications, Secrets Manager provides:
Secure storage
Automatic rotation
Encryption
Fine-grained access control
Audit logging

3. What Types of Secrets Can Be Stored?
---------------------------------------------------------------
Examples:
MySQL credentials
PostgreSQL passwords
API keys
OAuth tokens
JWT secrets
Application passwords

4. What is a Secret?
---------------------------------------------------------------
A secret is sensitive information stored securely as key-value pairs.

Example:
{
  "username":"admin",
  "password":"Admin123"
}

5. Is Secrets Manager Regional or Global?
---------------------------------------------------------------
Secrets Manager is a regional service.
Secrets are stored within a specific AWS region.

6. How Does Secrets Manager Secure Data?
---------------------------------------------------------------
Secrets are encrypted using:
AWS-managed KMS keys
Customer-managed KMS keys

Encryption occurs:
At rest
In transit

7. Which Service Performs Encryption?
---------------------------------------------------------------
Amazon Web Services KMS (Key Management Service).

8. What is the Default KMS Key?
---------------------------------------------------------------
aws/secretsmanager
AWS-managed key.

9. Can Customer-Managed KMS Keys Be Used?
---------------------------------------------------------------
Yes.

Benefits:
More control
Key rotation
Fine-grained permissions

10. What is Secret Rotation?
---------------------------------------------------------------
Automatically changing credentials periodically without manual intervention.

11. Why Use Rotation?
---------------------------------------------------------------
Benefits:
Improved security
Reduced credential exposure
Compliance requirements

12. How Does Rotation Work?
---------------------------------------------------------------
Application
      ↓
Secrets Manager
      ↓
Lambda Function
      ↓
Database Password Updated
      ↓
New Secret Stored

13. Which Service Performs Rotation?
---------------------------------------------------------------
Amazon Web Services Lambda.

14. Supported Rotation Targets
---------------------------------------------------------------
Amazon RDS
Aurora
Redshift
DocumentDB

15. Rotation Frequency Options
---------------------------------------------------------------
Example:
30 days
60 days
90 days

Custom schedules are supported.

16. Does Secrets Manager Support Versioning?
---------------------------------------------------------------
Yes.
Each update creates a new version.

17. Common Version Labels
---------------------------------------------------------------
Label			Meaning
AWSCURRENT		Current secret
AWSPREVIOUS		Previous secret
AWSPENDING		Rotation in progress

18. Why Is Versioning Important?
---------------------------------------------------------------
Rollback support
Safe rotations
Change tracking

19. How Is Access Controlled?
---------------------------------------------------------------
Using:

IAM Policies
Resource Policies
KMS Policies

20. Required Permission to Retrieve Secrets
---------------------------------------------------------------
{
 "Effect":"Allow",
 "Action":"secretsmanager:GetSecretValue",
 "Resource":"*"
}

21. Permission to Create Secrets
---------------------------------------------------------------
"Action":"secretsmanager:CreateSecret"

22. Permission to Update Secrets
---------------------------------------------------------------
"Action":"secretsmanager:UpdateSecret"

23. Common Secrets Manager APIs
---------------------------------------------------------------
Create Secret
CreateSecret
Retrieve Secret
GetSecretValue
Update Secret
UpdateSecret
Delete Secret
DeleteSecret

24. AWS CLI to Retrieve Secret
---------------------------------------------------------------
aws secretsmanager get-secret-value \
--secret-id MySecret

25. Create Secret Using CLI
---------------------------------------------------------------
aws secretsmanager create-secret \
--name dbsecret \
--secret-string '{"username":"admin","password":"Admin123"}'

26. What is a Resource Policy?
---------------------------------------------------------------
A resource-based policy attached directly to a secret.

Used for:
Cross-account access
Fine-grained permissions

27. Can Secrets Be Shared Across Accounts?
---------------------------------------------------------------
Yes.

Using:
Resource policies
IAM roles

28. How Do You Monitor Secrets Manager?
---------------------------------------------------------------
Using:
CloudTrail
CloudWatch

29. What Does CloudTrail Capture?
---------------------------------------------------------------
Operations such as:
CreateSecret
GetSecretValue
UpdateSecret
DeleteSecret

30. Why Use CloudTrail?
---------------------------------------------------------------
For:
Auditing
Compliance
Troubleshooting

31. Secrets Manager vs Parameter Store
---------------------------------------------------------------
Secrets Manager			Parameter Store
Automatic rotation		No automatic rotation
Paid service			Standard tier free
Versioning				Versioning
Designed for secrets	General configuration

32. Secrets Manager vs Hardcoded Passwords
---------------------------------------------------------------
Hardcoded				Secrets Manager
Insecure				Secure
Manual updates			Automatic rotation
Difficult to manage		Centralized

33. Secrets Manager vs Environment Variables
---------------------------------------------------------------
Environment Variables		Secrets Manager
Visible on host				Encrypted
Static						Rotatable
Less secure					Highly secure

34. How Does Lambda Access Secrets?
---------------------------------------------------------------
Through IAM roles.

Example:
import boto3
client = boto3.client('secretsmanager')
response = client.get_secret_value(
    SecretId='dbsecret'
)

35. Why Use IAM Roles Instead of Access Keys?
---------------------------------------------------------------
Temporary credentials
More secure
No hardcoding

36. How Does RDS Integrate with Secrets Manager?
---------------------------------------------------------------
Application
      ↓
Secrets Manager
      ↓
RDS Database

Passwords can rotate automatically.

37. Can Aurora Credentials Be Rotated?
---------------------------------------------------------------
Yes.

Supported databases include:
MySQL
PostgreSQL
MariaDB
Aurora

38. What Happens When a Secret Is Deleted?
---------------------------------------------------------------
Deletion is scheduled.
Default recovery period: 30 days

Minimum: 7 days

39. Can Secret Deletion Be Cancelled?
---------------------------------------------------------------
Yes.

Using: 
aws secretsmanager restore-secret

40. Is Secrets Manager Highly Available?
---------------------------------------------------------------
Yes.
It is managed and highly available within a region.

41. What Is Cross-Region Replication?
---------------------------------------------------------------
Replicates secrets to multiple regions.

Benefits:
Disaster recovery
Multi-region applications

42. Can Binary Secrets Be Stored?
---------------------------------------------------------------
Yes.

Examples:
Certificates
Images
Binary files

43. Maximum Secret Size?
---------------------------------------------------------------
64 KB

44. Can Tags Be Applied?
---------------------------------------------------------------
Yes.

Used for:
Cost allocation
Resource organization

45. Can Secrets Be Cached?
---------------------------------------------------------------
Yes.
Using AWS Secrets Manager caching libraries.

Benefits:
Reduced latency
Lower API calls
Improved performance

---------------------------------------------------------------

Resource policy restrictions

---------------------------------------------------------------

VPC configuration

48. Application Cannot Read Secret. What Will You Check?
---------------------------------------------------------------

49. Explain Your Secrets Manager Project
---------------------------------------------------------------
Example Answer:
"We stored database passwords and API keys in AWS Secrets Manager. EC2 and Lambda accessed secrets using IAM roles. 
Password rotation was automated using Lambda every 30 days. CloudTrail monitored all secret access events."

50. How Do You Secure Database Credentials?
---------------------------------------------------------------
Steps:
Store credentials in Secrets Manager.
Encrypt using KMS.
Enable automatic rotation.
Access through IAM roles.
Monitor using CloudTrail.
